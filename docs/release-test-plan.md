# 実機試験・エージング計画（`main`統合前）

作成日: 2026-09-28

状態: **計画。以下の実走・長時間試験は未実施。**
対象: M5Stack Tab5、GT-502MGG-N、車輪リードスイッチ、microSD、将来接続するエンジン系電装回路。PCテストの実施内容は[test/README.md](../test/README.md)、単体Tab5で既に確認した事項は[firmware-guide.md](firmware-guide.md#検証記録)を参照。

## 1. 判定の位置付け

現行の実装PRを`dev`へ統合する判断と、車両に載せる正式版として`main`へ統合する判断を分ける。この文書は後者の試験計画であり、現時点の合格報告ではない。試験で修正した場合は、修正後の**同一コミット・同一設定のファームウェア**で影響する試験をやり直す。

本番コースは本番まで走れない。実走は交通のある一般の道を自転車で走り、入力・表示・記録・制御の結合とGPS判定の性質を確認する。これで本番コースの測位環境、3地点の精度、実車のノイズ・電源条件まで証明できたとは扱わない。その残存リスクを最終判定票に明記する。

本番コースのGPS自動ラップが未実証のままなら、誤加算を避けるため**手動ラップ専用に切り替えられる機能を正式版の前提**とする。現在の実装は自動判定を任意に無効化できないので、これは追加実装・試験が必要な項目である。手動ラップボタンだけでは、自動判定の誤加算を防げない。

## 2. 準備と試験記録

### 2.1 必要な準備

| ID | 準備 | 完了条件 |
|---|---|---|
| P-01 | リリース候補を固定 | Git SHA、ビルド設定、ファームウェアのハッシュ、EEZ生成元、設定値、Tab5/SD/GPS/回路の型番・版を試験票に記録する。テスト用設定と本番用設定を取り違えない表示・記録を用意する |
| P-02 | 一般道でのGPS判定用データ | 安全に反復走行できる普通の道を選び、独立したGPS記録から**試験専用**の経路形状とスタート確認点・周回更新点・ゴール点を作る。試験用ビルドでは経路データだけを差し替え、判定ロジックは本番と共通にする。現在は茂木の経路形状が組み込み固定なので、Settingsで3地点を変えるだけでは実走の自動ラップは試せない |
| P-03 | 判定の観測手段 | GPS受信時刻・fixの有効性・位置・経路からの横距離/進行距離・通過の受理/拒否理由、リードの累積パルス、SDキューあふれを後から照合できる診断ログを追加する。通常の500 msサンプルだけでは、通過を取りこぼした理由を特定しにくい。ログはSDを詰まらせない有限・低優先度の経路とする |
| P-04 | 長時間監視 | 起動回数/リセット理由、稼働時間、空きヒープ/最大連続空き領域、各タスクのスタック余裕、SD失敗/キューあふれ数を収集できるようにする。現在の`status`だけでは長時間試験のメモリ傾向を判定できない |
| P-05 | 出力回路 | ECUを接続する前に、絶縁回路・ダミー負荷・オシロスコープ/ロジックアナライザを準備。未駆動・リセット中を含む電装OFF条件、実回路の極性、ECUが要求する待ち時間/パルス幅を回路仕様で確定する |
| P-06 | 証跡保全 | シリアルログ、SD原本、独立したGPS軌跡、試験票、波形、写真、問題票を同じ試験IDで保存する。公道GPSの生位置は公開PRへそのまま添付せず、公開用は必要範囲だけ匿名化する |

P-02〜P-04と手動ラップ専用モードは**現時点で未実装の試験準備**であり、既存テストで達成済みとは数えない。P-02を整える前でも、普通の道で車速・生GPS位置・手動操作・SD記録の試験は可能。

試験票には最低限、試験ID/日時、担当、天候・周囲温度、ファームウェアSHA、ハード/配線/電源、SDカード、設定値、手順、期待結果、実測値、証跡の保存先、合否、問題番号、再試験結果を記す。開始前・終了後に設定とSD残容量を記録し、電装出力はOFFと確認する。

### 2.2 判定区分

- **必須:** 合格証跡がない場合は`main`への統合を保留する。失敗を修正したら該当試験と影響範囲を再実施する。
- **条件付き:** 通信など本番で使う構成に応じて実施する。実施できない機能は正式版で無効化し、保留理由と運用上の影響を明記する。
- **本番コース依存:** 一般道では本番3地点の通過判定を証明できない。手動ラップ専用モードと運用手順を検証した上で、未検証リスクとして記録する。本番で得たログを次版の校正に使う。

以下の数値は**試験計画上の暫定合格基準**。走行前に回路仕様、独立測定器の精度、一般道のルート長を確認して試験票で確定し、試験後に結果へ合わせて緩めない。

## 3. 段階別の試験

### 3.1 卓上・静止状態（車両/ECUへ接続しない）

| ID / 必須 | 手順 | 合格基準と証跡 |
|---|---|---|
| B-01 / 必須 | 候補SHAでPCテスト、PlatformIOビルド、EEZ再生成確認、Tab5書込。通常起動と手動再起動を行う | すべて成功。起動時に電装OFF、始動LOW、SD状態が表示され、panic/watchdog/意図しない再起動がない。ログとビルドのSHAを保存 |
| B-02 / 必須 | GPSを屋外の見通しのよい場所に設置し、静止状態で少なくとも15分記録。受信開始・切断・再接続を行う | 有効位置と欠損/古い位置が区別される。切断後は設定の3秒を超えて最新fixとして扱わない。受信率・無効文数と独立GPS記録を残し、異常時は原因を分類する |
| B-03 / 必須 | リードスイッチを実ホイールで回し、別カウンタまたは撮影した回転数と比較。続いてパルス発生器で既知回数、開放10 ms未満/以上、75 km/h相当の周期未満/以上、設定の最小パルス間隔未満/以上を入力 | 短い再開閉は1回として扱い、60 km/hまでの実ホイールで1回転ごとのパルスを落とさない。停止後は設定の3秒で速度0。実ホイール周長を測り、1.03 mの暫定値を校正。生の立ち下がり・受理数・入力波形を保存 |
| B-04 / 必須 | GPIO45/48を絶縁回路とダミー負荷につなぎ、電源投入、通常再起動、電装ON/連打/途中OFF/再ON、電源喪失を波形で測る。電装極性の両設定を確認 | 未駆動・リセット中も回路側でOFF。ON後の準備待ち、1サイクル1回の始動、パルス中OFF、再ON後の再許可が実測で一致。現行1000 ms/1000 msは**暫定**で、ECU仕様確定値と計測許容差を試験票で決める。ECU接続前に全項目合格 |
| B-05 / 必須 | Settingsで全体/7周TARGET・3地点とAdvancedの13項目を変更して保存・再起動。計測中の変更と、電装ON中の極性・ECU準備・点火幅の変更も試す | 編集可能な27項目の永続保持。計測中はUIと中核が拒否。電装ON中の安全に関わる3項目も拒否。電装ON状態や途中レースは再起動後に復元せず、OFF/Waitingで起動。変更前後の設定ログを保存 |
| B-06 / 必須 | SDなしで起動・計測し、カードを挿した正常起動では開始→取消と記録読戻しを行う。書込失敗は安全な故障注入で再現する | SDなし/書込失敗を警告し、計測・表示・電装OFF操作は継続。正常カードではJSONL全行が読め、取消記録が残る。書込中のカード抜去は常用試験とせず、故障注入か使い捨てカードで別評価 |

### 3.2 普通の道を自転車で走る（エンジン系出力は未接続）

安全に固定したTab5、実GPS、実リードスイッチ、microSDを使う。走行中の小さな操作・シリアル操作・画面注視は行わず、操作と画面確認は安全な停止場所で行う。独立した自転車メーター/スマートフォンの記録と、可能なら同行者の通過記録を比較に使う。雨水・結露を避け、装置の固定と配線の引っ掛かりを出発前に確認する。

| ID / 必須 | 手順 | 合格基準と証跡 |
|---|---|---|
| R-01 / 必須 | **茂木の経路形状を入れたまま**、一般道で手動開始し、平坦/曲がり/停止を含む30分以上を2回走る。停止場所で表示を確認し、最後は一方を取消・他方を手動ラップ後に取消 | SD上の生GPS座標、画面のGPS鮮度、車速、停止を含む平均速度、経過時間、手動操作、SD記録が矛盾しない。電装OFFのままGPS・車速・計測が継続。茂木から離れた一般道では地図マーカーが表示範囲外になるため、位置の画面内表示とGPS自動ラップの合否は付けない。独立ログとの差を表にする |
| R-02 / 必須 | 独立メーターで距離が分かる1 km以上の区間を走り、開始/終了時の累積パルス、走行距離、停止時間を比較 | 欠落/二重パルスがなく、校正後の距離差が独立測定値の±2%以内を暫定目標とする。差が出たら周長誤差、入力回路、チャタリング、独立測定の誤差に分解して再試験 |
| R-03 / 必須 | P-02の**一般道用試験データ**で、周回地点と別のゴール地点を設定。安全な通常走行で7周相当を3回行い、各地点の通過を独立ログと照合。現状は完走後の再計測機能がないため、各回の間に再起動する | 各回で開始1/7→周回更新6回→7周目ゴールのみで完走。誤加算・取りこぼし・同一通過の二重加算が各0回。GPS欠損が出た回は条件と発生地点を記録し、修正・再試験する。閾値60 m/80 m/600 m/60秒/10秒は結果から校正し、後から無説明で合格扱いしない |
| R-04 / 必須 | 停止地点でGPS受信を遮る、コース外へ出る、手動ラップ直後に同じ地点を通過するなど、無理のない条件を作る | 古いfixやコース外位置で自動更新しない。手動補正と自動検出は二重加算しない。操作場所と独立軌跡を記録し、危険な逆走や急旋回は試験手段にしない |
| R-05 / 必須 | 日なた/日陰、電源接続/バッテリーで停止時に画面とタッチを確認。Settingsへの出入りと数字キーをそれぞれ100回操作し、1秒待ってからシリアルの`perf`を記録する。手動ラップ専用モードでも1回の開始・6回補正・取消を行う | 主要数値、警告、電装/始動の**指令状態**を読め、タップの取りこぼし・数秒の遅延が各0回。`perf`の`presses`と`delivered`が一致し、`overflow=0`、`touch_gap<128000` µs。手動専用時にGPSによるラップ増加が0回。写真と操作記録を保存 |

R-01/R-02はP-02がなくても実施できる。R-03/R-04は一般道用経路の実装が前提。安全な周回路を取れない場合は、実際に自転車で採った普通の道のGPS/UART記録を、実機入力へ再生して通過を検証する。ただし再生試験は**実走7周の代用**と記録し、屋外での測位・入力連携の合格とは分ける。

R-05のタッチ遅延に関する調査結果と`perf`の読み方は[タッチ応答遅延の調査と検証](touch-latency.md)を参照する。

### 3.3 通信・障害・電装回路

| I-02 / 必須 | 正常停止後の起動を繰り返し、別途、計測/SD記録中に電源断またはリセットを使い捨てカードで評価 | すべての起動で回路側の電装OFFと始動LOWを維持。再起動後はWaitingで、途中レースを復元したように見せない。途中ファイルの終端が欠け得ることを記録し、過去の完了ファイルを上書きしない。SD破損時も警告して操作継続 |

I-01を正式版で使わない場合は、通信設定を空のままオフライン動作を確認し、「通信機能未検証・運用では無効」を判定票へ明記する。I-03は車両回路ができるまで実施不可であり、**実車に接続して使う正式版**の合格項目から省略しない。

### 3.4 エージング

安定した外部電源と監視用PCを使い、Tab5公式仕様の動作温度範囲 **0〜40 °C** 内で行う。公式ページの電池駆動時間の目安は約6時間なので、下記48時間は電池だけで実施しない。温度・供給電圧・ファームウェアSHA・SD容量・起動回数・ログ断を記録する。[Tab5公式仕様](https://docs.m5stack.com/en/core/Tab5)

| ID / 必須 | 負荷と期間 | 合格基準と証跡 |
|---|---|---|
| A-01 / 必須 | **48時間連続通電**。待機、Settings遷移、電装OFF、GPS有効/欠損、Wi-Fi有効/切断（使用予定なら）を含める。画面は定期撮影または定時の目視記録を残す | 意図しない再起動、panic、watchdog、表示停止、操作不能、SDエラーの見逃しが0回。1分ごとの稼働時間/リセット理由/空きヒープ/最大連続空き領域/タスクスタック余裕を保存。ウォームアップ後にメモリの持続的な減少や危険な余裕不足がないことを時系列で判定 |
| A-02 / 必須 | A-01内で**少なくとも8時間の連続計測・SD記録**。GPSまたは通常UART再生、車輪パルス入力、画面更新を同時に動かす。終了時は取消してファイルを閉じる | JSONLが全行解析可能で、開始/終了イベントが一致。500 msサンプルの時系列逆転・2秒超の連続欠損・キューあふれ・書込失敗が0回。計測時間を独立時計と照合し、ずれがあれば原因を評価する。8時間なら理論上約57,600サンプルであり、開始/終了境界の差は別に説明する |
| A-03 / 必須 | **30回の通常起動/再起動**と、別枠でSD書込中の電源断を3回。電装回路はダミー負荷、カードは使い捨てとし、各回の出力を監視する | 起動のたびに電装OFF/始動LOW。設定の保持と新しい記録名、過去ファイルの非上書きを確認。書込中断の直近データは失われ得るが、復元できた範囲とカード状態を明記。起動失敗、電装ON残留、故障を正常扱いするUIは0回 |

A-01/A-02の監視にはP-04の計測項目を追加する。現状のファームウェアから取得できない値を「0件だった」と推定しない。SDカード抜去や電源断でFATが壊れる可能性があるため、試験専用カードを使い、原本をバックアップする。1秒ごとの`fsync`は直近1秒のデータ保存保証を意味しない。

## 4. `main`統合の判定

次を満たしたときに判定会で合否を記録する。

1. B/R/I/Aの**必須項目**に結果・証跡があり、重大な未解決不具合がない。I-03は実車に接続して使用する正式版の必須項目。
2. 暫定値（ECU準備/パルス各1000 ms、電装極性、車輪周長、GPS閾値、3地点、全体/各周TARGET）を実測・運用方針に基づき確定し、試験した値と正式版の値を照合する。現行の全体TARGET 42:00は大会制限39:16と異なるため、正式な設定の確認が必要。
3. 本番コースでの自動ラップ未検証を残存リスクとして記録し、手動ラップ専用への切替えとその動作を実証する。一般道の合格を本番コースの通過精度の合格に読み替えない。
4. 通信を本番で使うならI-01を通す。使わないなら無効設定と利用不能範囲を明示する。未実施試験と既知問題には担当者と対応期限を付ける。
5. 最終候補のソースSHA、ビルド成果物SHA、設定プロファイル、テスト結果を紐付ける。試験後の機能/依存ライブラリ/設定変更には影響評価と再試験を行う。

```text

本番コース依存の未検証事項・手動運用手順:
未解決問題（番号、影響、対応者、期限）:
判定: 合格 / 保留 / 不合格
判定者・判定日:
```
