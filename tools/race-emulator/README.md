# race-emulator

Tab5とAtomS3をPCにUSB接続し、ブラウザから走行試験を管理するローカルアプリです。コース・速度・車輪設定とGPS異常の時刻指定を試験ケースとして保存し、両機のシリアル出力をPC時刻付きで記録します。Tab5がUSBから一時的に消えても、AtomS3の走行とホスト側の記録は続きます。

## 準備

1. AtomS3とTab5を**それぞれPCのUSBへ接続**する。GPS UART、車速パルス、共通GNDは[AtomS3の配線表](../atoms3-simulator/README.md#接続)に従う。5V線や車両回路は接続しない。
2. AtomS3にはコースJSONを含むLittleFSと対応するファームウェアを書き込む。Tab5では同じコースを選び、GENERAL SETTINGSでGPS INPUTを`PORT.A`にする。microSDが利用でき、Waiting画面であることを確認する。
3. VS Codeのシリアルモニターなど、両機のUSBポートを占有するアプリを閉じる。

```sh
cd tools/race-emulator
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m race_emulator.web
```

ブラウザで <http://127.0.0.1:8765> を開き、AtomS3とTab5のUSBポートを個別に選択します。ポートが不明な場合は、一台ずつUSBを抜き差ししてポート一覧の差分を見てください。このサーバーはローカルPCからのみアクセスできます。ブラウザを閉じても試験は継続し、**サーバーを終了すると試験も終了**します。

## 試験の流れ

1. 「試験ケース」を選ぶ。新規・編集・複製で複数のケースを管理できる。
2. 2台の状態が接続中であることを確認して「試験開始」を押す。Tab5のコース、Waiting状態、PORT.A設定、microSD状態を開始前に照合する。
3. アプリがAtomS3を初期化し、コース・速度・車輪設定・GPS異常の初期値を設定する。その後Tab5の計測とAtomS3の走行を開始する。時刻指定の異常は走行開始からの経過秒数で投入する。
4. AtomS3がGOALに達すると試験を終了する。手動停止や最大試験時間の到達でも終了できる。**手動停止はAtomS3だけに送られ、Tab5の計測は取り消されません。** Tab5側の計測を終了・取り消す操作は実機で行う。

試験のログはGit管理外の`runs/<日時>-<ケースID>/`に保存されます。`case.json`はその試験で使った定義の写し、`events.jsonl`は両機の全シリアル行・送信コマンド・USB切断/再接続・起動マーカーをPCのUTC時刻付きで記録したもの、`result.json`は終了理由です。画面上では重要な行に絞り、チェックを入れると全行を表示します。

## 試験ケース

`testcases/*.json`はGitで管理できる試験仕様です。UIから編集するとこのファイルが更新されます。現状の時刻指定アクションはAtomS3のGPS異常コマンド`noise`、`bias`、`spike`、`dropout`、`invalid`、`corrupt`、`seed`に限定しています。通常の車速パルスは速度と車輪設定から生成されます。パルスへの異常注入はまだAtomS3側に機能がないため、ケースでは指定できません。

## 現時点の判定範囲

本アプリはAtomS3のGOAL、Tab5の状態、USB切断・再接続、起動メッセージ、シリアルログを記録します。試験終了時の`completed`は**AtomS3がGOALへ達した**ことを意味し、Tab5の周回判定やSD記録の合格を自動保証しません。`result.json`にTab5の最終phaseを残すので、Tab5のmicroSDログと照合してください。今後、期待結果の自動判定や車速パルス異常を追加するための土台です。

長時間の数百周試験では、Tab5の規定周回が終わると1計測は終了します。何百周も1回の計測として継続する機能はまだありません。ケース単位で繰り返し、Tab5の実機操作とログ確認を組み合わせてください。
