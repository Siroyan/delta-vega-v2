# 戦略に沿った走行試験

race-emulatorの試験ケースで「戦略に沿って加速・惰性走行」を選ぶと、Tab5と同じ戦略JSONのON区間で加速し、OFF区間で減速します。実車のGPIOを操作したり、Tab5の点火操作を読み取ったりする機能ではありません。

## ブラウザでの操作

1. 更新したAtomS3ファームウェアを用意し、race-emulatorへUSB接続する。
2. 試験ケースのコースと走行モードを選ぶ。
3. 適合する同梱戦略を選ぶか、「戦略JSONを読み込む」でStrategy Editorの出力を取り込む。Tab5にも同じJSONを配置して選択する。
4. 最高速度・加速度・減速率・開始速度を設定し、ケースを保存する。
5. Tab5で計測を開始してから、ブラウザでAtomS3を走行開始する。Tab5もUSB接続する方式では、ホストが計測開始を送る。

| 試験条件 | 範囲・初期値 | 意味 |
|---|---|---|
| 最高速度 | 1〜60 km/h、新規ケースは30 | ON区間で到達できる上限 |
| 加速度 | 0.01〜5 m/s²、0.3 | ON区間での速度の増え方 |
| 惰性での減速率 | 0.001〜2 m/s²、0.03 | OFF区間での速度の減り方 |
| 開始速度 | 0〜最高速度 km/h、0 | 静止から出発するなら0。最初のONが0 mでない戦略には必要に応じて初速を設定 |

元の`assets/strategy/*.json`と、Git管理外の`host/strategies/`に取り込んだJSONを選択できます。コースID・周回数・経路・距離が合うファイルだけを表示します。JSON全体の上限は4096バイトで、1周あたりの区間数制限はありません。Tab5が旧ファームウェアの場合、4区間以上の戦略にはTab5側の対応版も必要です。コースJSONは従来どおり`assets/maps/`の原本を使います。

## 運動モデルと試験結果

一定加速度による簡単なモデルです。坂・空気抵抗・実車の特性は再現しません。ON/OFF地点、速度上限、停止位置、周回境界までの時間を解析的に求めてから次の区間へ進みます。GPSと車速パルスは同じ距離・速度を参照します。GPSへのノイズや欠測を加えても、車両の移動と車速パルスは継続します。

惰性で次のON地点やゴールへ届かず速度が0になると、そこで停止し、ホストの試験結果を`stalled`にします。速度の下限による救済はありません。開始速度0で最初のONが0 mより先なら、スタート地点で停止します。同梱の短いデモ区間は表示確認用なので、物理条件によっては途中で停止します。

JSONの目標ゴール・ラップタイムは比較用です。目標時刻へ合わせる速度補正は行いません。Atomの画面には実速度と`ENGINE ON` / `COAST`を表示し、シリアルにはON/OFF地点・周回時間・目標時間を記録します。停止時の`STALL`も表示します。GOAL時は停止しますが、そこに至るまでの速度を積分した経過時間を記録します。

ホストは試験前に元のJSONをUSBで転送し、SHA-256と受理応答を照合します。読込・転送に失敗すると`setup_failed`として開始を止めます。実際に送信したJSONを`host/runs/<試験>/strategy.json`に保存し、`result.json`に`strategy_sha256`を記録します。試験中に元ファイルを編集しても、開始時の写しを使います。

従来のケースは「一定速度」として読み込みます。その試験を開始する際は、Atomに残っている戦略を明示的に解除します。古いAtomファームウェアでは準備を失敗させ、対応版への更新を表示します。

## Atom単体の操作

```text
stop
course motegi_oval_full
speed 30
dynamics 0.3 0.03 0
strategy motegi_demo.json
start
```

`speed`は戦略走行では最高速度です。`dynamics`の順序は加速度、惰性減速率、開始速度です。`strategy none`で一定速度へ戻ります。設定変更は走行・一時停止以外の状態で行い、STARTへ戻ります。コースの切替時は戦略を解除します。選択した戦略・運動条件はNVSに保存し、USBを外しても実行できます。読み込んだ戦略本体はLittleFSに保存します。

`uploadfs`時には同梱JSONを`/strategies/`へそのまま配置します。ホストから転送した戦略は`/host-strategy.json`です。ファイル領域を書き直すと転送済み戦略も消えるため、再選択または再転送してください。

シリアルの転送プロトコルは`plan-begin <バイト数> <SHA256>`、`plan-chunk <16進データ>`、`plan-end`です。ホストは48バイトごとの受信オフセットを確認します。最終応答のSHA-256が一致するまで走行を開始しません。

## 自動テスト

リポジトリのルートから実行します。

```sh
tools/race-emulator/host/.venv/bin/python -m unittest discover -s tools/race-emulator/host/tests -v
python3 tools/race-emulator/atoms3/scripts/test_motion.py
```

ホストのテストは旧ケース互換、条件検証、元JSONの保存・転送、受理失敗での開始禁止、失速を確認します。C++テストはAtom用の実装を直接実行し、解析解、細かい刻みと遅延した刻みでの一致、ON/OFF・周回境界、最高速度、失速、同梱JSON・8区間以上の読込を確認します。AddressSanitizerとUndefinedBehaviorSanitizerも適用します。

Atom単体をUSB接続して信号出力まで確認するには、以下を実行できます。短い試験用戦略を転送し、3回のON/OFF、NMEA速度の増減、パルス送出遅れ0、失速の記録を確認します。電気的な波形の測定やTab5側の受信確認は含みません。終了後は茂木デモ、最高速度30 km/h、加速度0.3、減速率0.03、開始速度0のREADYへ戻します。

```sh
tools/race-emulator/host/.venv/bin/python tools/race-emulator/atoms3/scripts/test_strategy_device.py --port /dev/cu.usbmodemXXXX
```
