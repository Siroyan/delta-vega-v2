# 玉川学園前駅周回・フィールドテスト用コース

指定された玉川学園前交差点を起点に、駅を道路で一周する約716 mの暫定コース。OpenStreetMapの道路中心線を基にしたもので、実際に歩く・走る位置やGPS軌跡で校正する前のデータである。

## 経路

1. **START**：玉川学園前交差点 `35.564980, 139.463466`。指定座標は道路中心線から約5 m離れているため、経路線は交差点のOSMノードへ接続した。
2. 駅の西側道路を南下する。
3. 南側の「玉川学園前1号」踏切を東へ渡る。
4. 駅の東側道路を北上する。この道路はOSMでは北向きの一方通行。
5. 北側の「鶴川5号」踏切を西へ渡り、交差点に戻る。

周回更新地点は北側踏切の西側、起点の約50 m手前に置いた。1周目は指定の起点からこの地点まで約660 m、2〜3周目は各約716 m。4周目は更新地点から駅西側道路を約254 m進んだ地点をゴールとする。約2.34 kmが4周完走までの参考経路長となる。

| 地点 | 緯度 | 経度 | 用途 |
|---|---:|---:|---|
| START | 35.564980 | 139.463466 | ドライバーの操作による計測開始位置の目安 |
| LAP | 35.5647900 | 139.4640418 | 1〜3回目の自動周回更新 |
| GOAL | 35.5633809 | 139.4629657 | 4周目の自動完走判定 |

## ファイル

- `tamagawagakuen_course.json`：WGS84座標、経路の累積距離、座標から480 px画像への変換行列、4周の経路、判定地点。既存の茂木コースと同じschema version 2。
- `tamagawagakuen_course.svg`：480 × 480 pxのコース原画。淡い線は小田急線の位置の目安。
- `tamagawagakuen_course_480.png`：Tab5用の背景画像。START・LAP・GOALの印はファームウェア側で重ねる想定。
- `tamagawagakuen_course_preview.png`：地点と周回更新線を重ねた確認用画像。

`platformio.ini`で`VEGA_TEST_COURSE=1`にすると、このコースの座標と画像を実機へ組み込む。テスト版はEEZの生成物を起動時に画像だけ差し替え、設定を通常の`vega`とは別のNVS領域`vega-test4`に保存する。以前の`vega-test`設定があれば読み込み、全体目標が旧初期値の70分なら40分へ更新する。新規の初期値は3地点、コース回廊30 m、各周10分・全体40分。茂木用のmicroSD走行戦略は読み込まない。MQTTは現在のビルド設定では有効で、計測中のサンプルは通常のAWSトピックへ送信される。

`VEGA_TEST_COURSE=0`で再ビルドすると茂木のコース・EEZ画像・通常のNVS設定を使用する。このテストコースにはゴール分岐がないため、実機では`FinishApproach`経路を設けず、4周目の通常経路上のGOAL判定を使う。4周目にはMANUAL LAPボタンも手動GOALへ変わる。Settingsでは未使用のLAP 5〜7を隠す。

## 初回の現地校正

まず`MIN LAP PROGRESS`は現行の600 m、`MIN LAP TIME`は60秒のまま、`COURSE CORRIDOR`を30 mとして試す。作成した経路上の模擬位置では600 m条件で1周目・通常周回の判定が成立した。ただし1周目は約660 mなので余裕が約60 mしかない。現地のGPS記録で周回を取りこぼした場合に限り、進行距離の条件を500 m程度へ下げて再試験する。ゴール判定には現行ファームウェアの固定条件として100 m以上の前進が必要で、LAPからGOALまでは約254 m確保した。踏切・交差点では通常の交通ルールに従い、端末の操作と表示確認は停止中に行う。

## 出典とライセンス

道路・踏切・線路の形状は[OpenStreetMap contributors](https://www.openstreetmap.org/copyright)のデータ（ODbL 1.0）を使用した。取得範囲と道路way IDはJSONの`source`に記録した。駅の位置関係は[小田急電鉄の駅案内](https://www.odakyu.jp/station/tamagawagakuen_mae/index.html)とも照合した。経路の道路中心線は測量値ではなく、通行可否や現地の交通規制は実走前に確認する。

## 実機での初期確認

2026-10-01にテスト版をTab5へ書き込み、Waiting画面の新しいコースとSTART・LAP・GOALを目視確認した。シリアルでは`course_id=tamagawagakuen_station_loop_test_v1`、地点のSettings値、電装OFF、SD正常、GPS入力先PORT.Aを確認した。Wi-Fi/MQTT/NTPは起動後に接続した。

2026-10-02にPort.A Unit GPSをWalking modeとして実際に一周歩き、GPSによるLAP 1→2の更新と画面表示を確認した。受信軌跡は約764 m。GPSの長時間停止は前回のPortable mode試験より大幅に減った。一方、SD記録は計測途中で書込みが止まり、取消の終了イベントが残らなかった。原因は調査中。4周目の自動ゴール判定は未試験。
