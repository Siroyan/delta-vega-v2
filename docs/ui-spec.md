## 1. 目的と対象範囲

Hondaエコマイレッジチャレンジのドライバーが、速度・周回・経過時間と目標時間・現在位置を短時間で把握できる車載画面を作る。走行中は主画面だけで必要な情報と操作が揃い、ページ切り替えや小さな操作を必要としない構成とする。

対象レースは7周。大会制限時間はユーザー申告で39:16以内だが、初期実装の全体TARGETは暫定42:00、各周TARGETはすべて06:00とする。大会制限と走行戦略の目標は別の値であり、暫定TARGETが大会制限を満たすことを意味しない。全体・各周TARGETはSettingsで変更できるようにする。スタート・周回更新・ゴールは別地点とし、6.3の初期座標を設定で変更可能にする。固定表示のサンプル値を設定初期値や大会ルールとして流用しない。

本書は表示と操作、そのためのデータ境界を定義する。走行プランの解析・最適化は後回しとし、先にコース表示と車載UIを完成させる。将来の走行プランを受信・表示する場所と状態は確保する。

## 3. 合意済みの基本方針

- 1280×720、横向き。白基調、濃い文字、少ない装飾、大きな数値。
- ドライバーは画面の見方を事前に学ぶ前提とし、走行中の画面に操作説明や色の凡例を常設しない。地図上の説明・重複する状態ラベルを省き、数値・コース・操作指示の視認性を優先する。
- 現在速度を最も目立たせる。平均速度、周回数、全体時間、ラップ時間も常時表示する。
- `HEARTBEAT UI`、`PULSE INPUT`、`GPS FIX`等はデバッグ用の小さなインジケーターとする。ドライバー向けの速度・時間・操作領域を優先する。
- 電装系の`OFF` / `STANDBY`トグルを左下、エンジン点火ボタンを右下に常設する。電装は青緑、点火は赤の大きな円形操作領域とし、互いに色とアイコンで区別する。通常の青い操作ボタンとも形状で区別する。円の外周は画面外に少しはみ出してよい。
- 小さな現在時刻とNTP同期状態を表示する。ドライバー向けのレース経過時間とは用途を分ける。
- 全体・ラップとも、現在の経過時間と目標時間だけを表示する。目標時間の見出しは両方とも`TARGET`とし、`LIMIT`や残り時間の見出し・数値は表示しない。
- 手動ラップボタンは周回数の右側に置く。次の操作案内は左右下隅の重要操作の中間に置き、大きな文字で表示する。
- コース名・データ年の注記ラベル（`course_sample_label`）は画面に表示しない。
- 地図に設定済みのスタート・ゴール地点と現在位置を表示する。PlanDemo・CachedPlanの静的な例に沿い、MainにはmicroSDから読んだ各周のエンジンON/OFF地点と加速・惰性区間を重ねる。
- 初回の計測開始はドライバーのボタン操作。その後のラップ更新はGPSで自動化する。
- GPSによる周回の取りこぼしに備えて、走行中も大きな「手動ラップ＋1」ボタンを常設する。
- 重い解析は将来AWSで行う。Tab5は受信したプランを表示し、通信断でも計測・表示を継続する。
- コースはGPS対応の座標データを持ち、同じデータから生成した背景画像に動的要素を重ねる。
- 車速・GPSはTab5がM5BusのGPIO・UARTから直接取得する。車速はリードスイッチ、車輪周長1.03 m、1回転1パルス。GPSはGT-502MGG-N。
- 初期実装から計測中のmicroSD保存を必須とする。SD障害時も警告しつつ計測を続ける。通信断中のデータの自動後送信と再起動後の計測復元は初期実装に含めない。
- システム全体はPorts and Adapters、表示側はMVPとする。責務と依存関係は[architecture.md](architecture.md)を参照する。

### 4.2 見た目と文字

- 白背景、本文は濃いグレー。区切りは薄いグレー、計測開始・手動ラップ等の通常操作は青を基本とする。電装は青緑、点火は赤の円形として重要操作を区別する。
- 現行フォントはRicty Diminished。現在速度160 px、平均速度・経過時間96 px、周回数64 px（Finishedの`FINISHED`は32 px）、`TARGET`の行48 px、速度・時間・LAPの見出し32 pxとする。速度・経過時間・目標時間の読みやすさを保つ。`LAP`の見出しは`AVERAGE SPEED (km/h)`と同じRicty Diminished 32 pxにし、領域を（24, 444, 360, 28）とする。平均速度は、見出しを（24, 302, 360, 28）、数値を（24, 334, 260, 83）に配置する。現在速度の数値領域下端と平均速度見出しの間隔は26 pxとする。
- 電装・点火の円形領域は直径208 pxを維持する。電装は青緑（#087F8C）、点火は赤（#B43832）を基本とする。外周は画面外へ48 px程度はみ出してよい。
- 左下は円形そのものが2状態トグルとなり、内側のスライダーとノブは置かない。OFFは淡い背景＋青緑の太枠、STANDBYは青緑の塗りつぶしとする。`STANDBY`の文字は表示せず、棒と丸の電源アイコン（96×96 px）のみを表示する。右下は白い炎アイコン（108×108 px）を主表示とする。左右の円形操作はアイコンのみとし、`ELECTRICAL`・`IGNITION`・`PRESS`等の文字は表示しない。円の見切れによる視覚的な偏りを補正し、電源アイコンは円の中心から右上へ各12 px、炎アイコンは左上へ各12 pxずらす。アイコン領域は電源が96×96 px・円内座標（68, 44）、炎が108×108 px・円内座標（38, 38）となる。炎は絵柄の見かけの大きさを電源に近づけるため、電源より12.5%大きい寸法とする。電源アイコンにチェックマーク等の補助マークは添えない。表示内容は画面内に収める。
- 時計、NTP同期状態、デバッグ表示は16〜24 px程度でよい。デバッグ用LEDや余白も小さくする。
- 既存の24/32/48/64/96/120/160 pxフォントは利用可能な候補であり、すべてを使う必要はない。追加サイズはEEZで必要な文字だけ生成する。
- 全体・ラップの時間欄は現在の経過時間と`TARGET`の2項目にする。残り時間や超過時間の数値、`REMAINING`・`LIMIT`・`OVER`の見出しは置かない。Overtimeでは経過時間をそのまま表示し、経過値を赤くした表示例を用意している。
- 目標未設定時は目標の行を`TARGET NOT SET`とする。
- 次の操作案内は左右の円形操作の中点（画面中央x=640）に揃え、`PLAN EXPIRED`等の主表示は64 pxの大きな文字で表示する。補足は24 px程度とする。
- 正常・異常やプランの状態は色だけでなく、短い文字・形状を併用する。
- 電源・炎はLucideのオープンなSVGアセットを使用し、透過PNGとしてEEZに埋め込む。原本・派生画像・取得元は`assets/icons/lucide/`に保存する。ISC LicenseとFeather由来のMIT Licenseの全文・著作権表示を同梱し、生成画像やファームウェアの配布にも添付する。絵文字フォントの有無に依存させない。
- 日本語ラベルを使う場合は必要な字形を生成対象に含める。開発中の英語ラベルとの混在は最終段階で整理する。
- 桁数が変わってもレイアウトが揺れない幅と配置にする。欠損を数値0で代用しない。

## 5. 表示項目と意味

| 項目 | 表示例 | 定義・挙動 |
|---|---|---|
| 現在速度 | `25.2` | 単位は見出し`CURRENT SPEED (km/h)`に示し、独立した単位ラベルは省略する。最新の有効な車速を表示し、未受信・古い値は`--.-`等で区別 |
| 平均速度 | `24.6`（見出し`AVERAGE SPEED (km/h)`） | 計測開始後の車輪パルス積算距離÷経過時間。停止時間を含める。周長1.03 m、1回転1パルス |
| 現在周回 | `3 / 7` | 走行中の周回番号。内部の完了周回数とは分離する |
| 全体経過 | `12:34` | 手動開始イベントを起点とする経過時間 |
| 全体目標 | `TARGET 40:00` | 全体の設定時間。初期値42:00。大会制限39:16とは別。数値例40:00は現行静的UIの表示のみ |
| ラップ経過 | `02:18` | 現在ラップの開始イベントからの経過時間 |
| ラップ目標 | `TARGET 05:00` / `TARGET NOT SET` | 初期値は1〜7周目すべて06:00。Settingsで周別に編集。数値例05:00は現行静的UIの表示のみ。将来は採用済みプランにも対応 |
| 次の操作 | `NEXT ON IN 120 m` | 採用中プランに基づくコース沿いの前方距離。直線距離ではない |
| 電装系 | 電源アイコンのみ | 円形トグルでOFF / STANDBYを選択。STANDBYの文字は省き、背景の塗り・枠で状態を表す。計測開始とは別操作 |
| エンジン点火 | 炎アイコンのみ | ECUへの始動パルス指令。電装ONごとに1回。エンジン実運転状態は取得できない |
| 現在時刻 | `13:45:08 JST` | 小さな24時間表記の時計。表示タイムゾーンはJST |
| NTP同期状態 | `NTP SYNCED` / `NTP HOLDOVER` / `NTP UNSYNCED` | 時計に隣接して小さく表示。同期済み・最終同期後の継続表示・未同期を区別 |

各周TARGETは走行戦略上の目標であり、周回ごとの公式制限ではない。全体・各周を編集可能にすることは合意済み。全体TARGETと各周TARGETは独立した設定とし、合計一致を強制しない。時間入力はMM:SSまたはH:MM:SSとする。

レースの経過時間は原則`MM:SS`、1時間以上では`H:MM:SS`に対応できるようにする。`99:59`等への切り捨てや折り返しはしない。

レースの経過時間はTab5の単調増加時刻を基準にする。現在時刻の時計はNTPで同期した時刻を表示し、NTPによる時刻補正でレース時間が飛んだりリセットされたりしない構成とする。通信受信時刻、GPS時刻、車載送信元の経過時間は区別する。既存ログで`timestamp_ms`と`total_time_ms`に差がある件は、将来の解析で別途解決する。コース形状には影響しない。

## 6. 状態と操作

### 6.1 画面状態と確認用ページ

EEZには以下の11画面がある。10種類のダッシュボードは同じ基本配置を使い、数値・状態・地図の表示例だけを変えている。

| EEZ画面名 | 現行の表示例 |
|---|---|
| Main | 走行中の主画面。戦略があれば現在周回のON/OFF地点・区間と次の操作を表示。未設定なら`PLAN NOT SET` |
| Waiting | 開始待ち、電装OFF、手動ラップ無効、`START TIMING`、NTP未同期 |
| Finished | 完走、`FINISHED`、手動ラップ／ゴール無効、`TIMING COMPLETE` |
| GpsStale | 最終位置を淡色表示。通知`Position stale / Timing continues`。地図下端の状態文は表示しない |
| MissingData | 速度・平均速度は`--.-`、ラップ目標は`TARGET NOT SET`。地図下端の状態文は表示しない |
| Overtime | 全体`1:00:12`、ラップ`05:12`。経過値を赤く表示し、残り時間・超過時間の数値は表示しない |
| PlanDemo | 模擬プランの加速・惰性区間、点火・停止地点、`NEXT ON IN 120 m` |
| CachedPlan | PlanDemoと同じ地図表示。上部`PLAN CACHED`、通知`Link offline / Plan valid`、NTP HOLDOVER |
| ExpiredPlan | 上部・下部中央`PLAN EXPIRED`。地図のプラン区間・ON/OFF地点を非表示とし、現在位置は表示 |
| LapCorrected | 手動補正後の表示例。通知`Lap corrected / Manual / approx.` |
| Settings | 全体・7周のTARGET、3地点の緯度経度、数値編集、保存、確認付き計測取消 |

実機ではWaiting/Main/Finishedを計測状態に応じて表示し、計測・車速・GPS・電装・時計・通信・SDの実状態を反映する。他の7ダッシュボードはEEZでの静的なデザイン例として保持し、機器操作は無効にする。計測開始・手動ラップ・電装トグル・始動・設定・取消は生成コード外のMVP経路でApplicationへ接続する。外部センサー未接続時は架空の速度や位置を表示しない。

| 状態 | 時間・周回 | 周回数の右（手動操作） | 下部中央（計測開始／案内） |
|---|---|---|---|
| 開始待ち | 経過`00:00`、周回`- / 7` | 手動補正は無効 | `START TIMING` |
| 計測中 | 経過時間・現在周回を表示 | 1〜6/7は`MANUAL` / `LAP +1`、7/7は`GOAL` / `FINISH` | 次の操作。プラン未設定は`PLAN NOT SET` |
| 完走 | 確定した結果を保持、周回欄は`FINISHED` | 手動操作は無効 | `TIMING COMPLETE` / `RESULT HELD` |

左下の電装トグルと右下の点火ボタンは、上記の計測用操作とは独立して同じ位置に常設する。

GPS未受信やクラウド未接続は「計測中」に重なる状態として扱い、通信異常だけで計測を停止しない。初期版はGPS未受信でも開始操作を許可し、GPS自動ラップが利用できないことを表示する。

### 6.2 計測開始

- 明確な押下1回で開始する。開始操作と初回ラップ完了を混同しない。
- 開始時に完了周回数0、現在周回1、全体・ラップの経過0とする。
- 開始前に横切った計測線や開始ボタン直後の同じ線を、1周完了として誤認しない。
- 計測開始後は開始ボタンを次の操作案内へ切り替える。再押下でリセットされる動作は設けない。

### 6.3 GPS自動ラップ

- 指定された計測線を、指定方向に通過したイベントを使う。
- GPS位置の有効性・鮮度に加え、前回検出からの進行量・時間等を確認して二重検出を防ぐ。
- 基準経路の距離原点を跨いだだけで自動ラップが確定する仕様にはしない。
- スタート・周回更新・ゴールの地点を別々の設定で持つ。初期座標は以下のとおり。いずれもユーザー指定の近似値で、後から編集可能とする。

| 地点 | 緯度 | 経度 | 用途 |
|---|---:|---:|---|
| スタート | 36.530654 | 140.227998 | 開始位置の確認。自動開始判定には使わない |
| 周回更新 | 36.532766 | 140.226269 | 通過ごとに現在周回を更新 |
| ゴール | 36.534443 | 140.225411 | 7周目のみ完走を判定 |

- 手動開始で1/7。周回更新地点の6回の有効な通過で7/7となり、その後ゴール地点を通過して完走する。手動ラップ補正も同じ周回管理へ反映する。
- ゴール地点を1〜6周目に通過しても完走しない。7/7に達しただけでは完走しない。
- 1地点の緯度経度だけでは通過線の幅・方位は定まらない。基準経路を使う判定方式、方向・判定範囲・重複抑制の閾値は実機・ログ評価で調整する。初期座標は現行経路から約11〜38 m離れており、無条件にGPSを経路へ吸着させない。
- CSVから置いた距離原点は仮設定であり、周回更新地点とは別に扱う。

### 6.4 手動ラップ補正

- 計測中の1〜6/7では周回数の右側に青い「手動ラップ＋1」を表示する。7/7では同じ168×90 pxの領域を赤い`GOAL` / `FINISH`に切り替える。上端を左側のLAP見出し（y=444）、下端を周回数表示の下端（y=534）に揃える。左下の青緑の電装操作とは別の領域にする。手動ラップは周回更新後10秒間無効にする。GPS自動周回後は、GPSが有効かつコース上にいる間、次周の進捗が最小距離に達するまで手動ラップも無効にする。GPS喪失・コース外では手動補正を許可する。7/7の手動ゴールは確認画面で誤操作を防ぎ、10秒待ちを加えない。
- 取りこぼしたラップを素早く補正するため、毎回の確認ダイアログは出さない。
- タッチチャタリング・長押しによる連続加算を防ぐ。押して離す1操作につき1回を原則とする。
- GPSによる自動検出と近接した手動入力は同じ通過イベントとして照合し、二重加算を防ぐ。
- 手動入力が受理されたら「ラップ補正を反映」等の短い通知を表示する。

**初期実装の補正時刻:** ボタン操作の受理時刻を採用し、「手動・時刻概算」と記録する。未確定のGPS候補から時刻を推定する処理は含めない。後から押した時刻を実際の通過時刻と偽って扱わない。全体の経過時間は補正でリセットしない。

**初期実装:** ラップ単位の「元に戻す」は提供しない。レース全体の取消はSettings/メニューから行う。自動/手動のラップ更新は10秒の重複抑制を共有し、手動操作時はGPS周回検出器を再初期化する。短いGPS欠落では既走行の進捗を保持するが、欠落中の通過は推定しない。閾値は実走行で校正する。

### 6.5 完走と計測取消

7周目の所定のゴール通過を確認した時点で完走とする。GPSでゴールを取り逃した場合は、7/7の`GOAL` / `FINISH`から確認画面を開き、`FINISH TIMING`で現在時刻の結果を確定できる。`KEEP TIMING`では計測を継続する。確認画面中も電装OFF操作を受け付ける。画面上の「7 / 7」になった瞬間は7周目開始であり、完走ではない。ゴール地点は周回更新地点と異なる。

完走前は計測取消を可能にする。取消後は開始待ちへ戻り、新たな手動開始でやり直せる。取消した計測のSD記録は残し、取消として区別できるようにする。完走後の再計測機能は初期実装に含めない。

走行中に触れやすい場所へリセットボタンを置かない。取消はメニューまたはSettingsから確認画面を開き、CANCEL TIMINGで確定、KEEP TIMINGで継続する。電装OFFは計測取消ではなく、時間計測・表示は継続する。

### 6.6 電装系のOFF / STANDBY

- 左下の円全体をチェック可能な状態保持型トグルボタンにする。1回のタップでOFF / STANDBYを切り替える。円の上にスライダーやノブを重ねない。
- 円は208×208 pxを維持し、画面内に見える円全体をタッチ対象にする。左端・下端は画面外へ48 px出すが、電源アイコンは画面内に収める。
- OFF時は淡い背景（#E6F3F4）・5 pxの青緑枠・濃い青緑の電源アイコンを表示する。STANDBY時はCHECKED状態として青緑の背景（#087F8C）・3 pxの濃い枠・白い電源アイコンを表示する。色だけに依存せず、塗りと枠の太さでも選択状態を区別する。
- 電装操作はアイコンのみとし、`ELECTRICAL`・`OFF`・`STANDBY`等の文字は表示しない。CHECKED状態の背景画像・背景色・枠はLVGLの状態スタイルで切り替え、指を離しても選択状態を保持する。
- 電装状態とレースの開始待ち・計測中・完走は別の状態として扱う。電装操作に計測開始・手動ラップ補正・計測リセットを割り当てない。
- 制御対象はエンジン系電装の給電。Tab5・車速・GPSは電装OFFでも動作を継続する。M5BusのGPIOから絶縁回路を介してエンジン系ハーネスへ接続する。
- 初期仕様はHIGHでON、LOWでOFF。回路は未製作のため極性は変更可能な設定値とする。Tab5起動・再起動時はOFFとし、明示的なON操作まで維持する。以前のON状態を自動復元しない。
- 電装の実状態を確認する信号はない。CHECKED表示はTab5が出力する電装ON指令の状態であり、リレー動作や実際の給電成功を保証する表示ではない。
- 回路側でも、Tab5出力未駆動・リセット中に電装OFFを維持する条件を満たす。ファームウェア初期化前のOFFはソフトウェアだけでは保証できない。
- 電装ON後はECU準備待ちとして暫定1000 ms点火操作を無効にする。待ち時間はECU仕様確認後に変更する。電装OFF時は始動パルスもLOWに戻す。

### 6.7 エンジン点火スイッチ

- 右下に大きな赤い円形ボタンを常設し、白い炎アイコンのみを大きく表示する。`IGNITION`・`PRESS`等の文字は表示しない。左下の青緑の電源アイコンと色・図柄で区別する。
- 直径208 pxの円形ボタンとし、右端・下端は画面外へ48 px程度出してよい。画面内に見える円形部分でタッチでき、炎アイコンは画面内に収める。
- 電装トグル、計測開始、手動ラップ補正と別の操作領域にする。地図上のON/OFF予定地点や次の操作案内からも独立させる。
- 点火スイッチの表示はドライバーの操作・点火指令を表し、エンジンが実際に運転中であることを操作だけから確定表示しない。
- 電装ON・ECU準備待ち完了・始動指令未送信のときに限り操作可能とする。電装OFF、準備待ち、送信済みではボタンを無効にする。
- ECU準備中は、電装OFF・点火済みと同じ薄い赤を円の背景にして、上端から時計回りに操作可能時の通常の赤で塗り進める。進行表示はボタン全体を覆い、別色の縁取りを残さない。進行度は設定されたECU準備時間と実際の待機状態から算出する。準備完了時に全面を通常の赤へ戻し、電装OFF・点火済み・出力エラー時には進行表示を消す。濃い赤は指がボタンに触れている押下表示に使う。炎アイコンとタッチ領域は変えない。
- 1回の押下でECU向けGPIOをLOW→HIGH→LOWにする。HIGH時間は暫定1000 ms、確認後に変更可能とする。待ち時間・パルス中もUI・計測は継続する。
- 電装ONの1サイクルにつき始動指令は1回まで。操作受理時に消費済みとして、連打や重複イベントによる再送信を防ぐ。電装OFF→ONで新たなサイクルとなる。
- スターター・点火の動作と自動停止はECU・車両側が担当する。Tab5は始動後の運転時間を管理せず、早期停止の操作は電装OFFのみとする。
- エンジンの始動成功・運転継続・自動停止の確認信号はない。時間経過や速度から実運転状態を確定しない。

### 6.8 ナビゲーションメニューと設定画面

- 左上の56×56 pxボタンに32 pxのハンバーガーアイコンを置く。10種類のダッシュボードすべてで同じ位置に表示する。
- タップすると幅384 px・高さ720 pxの白いパネルを左端に表示し、画面の残りを半透明の暗い背景（#202B36、opacity 100/255）で覆う。表示中は背景の操作領域へのタッチを遮断する。
- パネル上部の閉じるアイコン、またはパネル外の背景をタップすると閉じる。パネル内の余白をタップしても閉じない。
- メニュー項目は`SETTINGS`のみ。ボタンは（24, 112, 336, 88）、設定アイコンは40 pxとする。PlanDemo等の確認用ページへの切り替え項目は追加しない。
- `SETTINGS`を押すとSettings画面へ遷移する。戻るボタンは（16, 12, 56, 56）で32 pxの矢印アイコン、タイトルは（96, 26, 1100, 43）で48 px文字とする。設定はNVSへ保存する。戻る操作は未保存の編集を破棄し、現在のレース状態に対応するダッシュボードへ戻る。
- Settingsの左側には全体と7周のTARGET、右側にはスタート・周回更新・ゴールの緯度と経度を配置する。右側の最下段には`DISPLAY BRIGHTNESS`のスライダーと現在値（%）を置く。左下の`ADVANCED SETTINGS`から車輪・GPS・周回判定・ECU関連の13項目とGPS接続先を開く。Advanced画面はSettingsと同じ見た目・2列構成とし、右側の最下段に`GPS INPUT`の`M5BUS` / `PORT.A`二択を配置する。選択中のボタンを青く表示する。戻る矢印はSettingsへ戻す。両画面の編集内容は共通の一時設定に保持する。
- 数値をタップすると編集オーバーレイを開く。左上の戻る矢印はその項目の編集を破棄し、SETは編集値を一時設定へ反映する。GPS接続先は二択のボタンで選ぶ。明るさはスライダー操作中にプレビューし、保存せずSettingsを閉じると元の明るさに戻す。表示が読めるよう明るさの下限を64/255、初期値を従来と同じ127/255にする。SAVE SETTINGSで27個の数値項目・GPS接続先・明るさをまとめてNVSへ保存する。Settingsからダッシュボードへ戻ると未保存の編集は破棄する。
- Advanced画面の電装極性は`POWER HIGH`として`1`=HIGHでON、`0`=LOWでONを表示する。単位は各ラベルに記す。値は中核の設定検証を通し、範囲外や不正な形式は受け付けない。
- 計測中は数値編集・GPS接続先の切替・明るさの変更・保存を無効にする。GPS接続先の保存に成功した場合はUARTと受信状態を初期化する。取消はダッシュボードのメニューまたはSettingsのCANCEL TIMINGから行い、確認画面でCANCEL TIMINGを押すとWaitingへ戻る。KEEP TIMINGで計測を継続する。記録済みデータは保持する。
- 電装ON中は電装極性・ECU準備時間・点火パルス幅の編集ボタンを無効にし、アプリケーション側でも変更を拒否する。
- 設定画面の戻るアイコンで、メニューを開いたダッシュボードに戻る。画面を再作成せず、表示値・電装トグルの状態を維持する。
- ハンバーガー・閉じる・戻る・設定アイコンもLucideのアセットを使い、元SVG・派生画像・ライセンスを既存のアイコン用フォルダで管理する。
- EEZのCLICKEDイベントに`open_menu`・`close_menu`・`open_settings`・`open_advanced_settings`・`close_advanced_settings`・`return_to_dashboard`のネイティブアクションを設定する。実装は`src/app/ui_navigation.cpp`に置き、EEZ再生成で失われないようにする。

### 7.1 時計とNTP同期状態

- 時計と同期状態を状態バーに小さく並べる。ドライバーが走行中に読むことを前提にせず、速度・時間・大きなスイッチの領域を優先する。
- 同期済みは時刻と`NTP SYNCED`を表示する。未同期で有効な時刻がない場合は`--:--:--`と`NTP UNSYNCED`を表示し、仮の時刻を同期済みとして扱わない。
- 最終同期後に通信が途切れても時計表示は継続できる。同期の鮮度が基準を超えた場合は`NTP HOLDOVER`等で区別する。判定時間は実装時に決める。
- NTP状態はGPS・車載通信・プランの状態から独立させる。NTP未同期でもレースの計測開始・経過時間・手動ラップ補正を妨げない。
- 静的UIでは同期済み・未同期・最終同期後の継続表示の見た目を確認できるようにする。

### 8.2 座標変換

`coordinate_system`の原点・係数を使い、緯度経度から東・北のメートル座標へ変換する。

```text
east  = (longitude - origin_lon_deg) * east_m_per_lon_deg
north = (latitude  - origin_lat_deg) * north_m_per_lat_deg

x = M[0][0] * east + M[0][1] * north + M[0][2]
y = M[1][0] * east + M[1][1] * north + M[1][2]
```

`M`はJSONの`render.local_to_pixel_matrix_2x3`。得られた画像内座標に画面内の画像配置位置を加える。画像の拡縮・回転を変更する場合は、オーバーレイにも同じ変換を適用する。緯度経度の差分はdouble精度で計算する。

### 8.3 重ね描き

下から順に、コース背景、加速・惰性区間の線、エンジン操作地点、周回更新線、スタート・ゴール、現在位置、状態表示を重ねる。

PlanDemo・CachedPlan・ExpiredPlanの地図内には`plan_demo_label`、`plan_legend_label`、状態ラベル（`cached_status_label`・`map_status_label`）を置かない。`PLAN DEMO`・`ORANGE: ACCEL / BLUE: COAST`・`CACHED / VALID`・`PLAN EXPIRED`の重複表示を削除し、プラン状態は上部と下部中央の専用領域で伝える。

| 要素 | 表現 |
|---|---|
| スタート | 設定済みの緯度経度に置く青緑（#087F8C）の点。`START`ラベルは地図下端の凡例に表示。GPS未受信でも表示 |
| ゴール | 設定済みの緯度経度に置く赤（#B43832）の点。`GOAL`ラベルは地図下端の凡例に表示。GPS未受信でも表示 |
| 周回更新 | 設定済みの周回更新座標を基準経路へ投影した地点に、コースの進行方向と垂直な紫（#6F42C1）の線を描く。地図下端の凡例は`LAP` |
| 現在位置 | 背景やプランの線と区別できる濃色の矢印 |
| エンジンON | IGNITIONボタンと同じLucideの炎の形。44×44 pxのオレンジ（#DB741D）の円を背面に置き、40×40 pxの炎は白い縁取りと同じオレンジの塗りで示す |
| エンジンOFF | 24×24 pxの青い四角（#1769B2） |
| 加速区間 | オレンジ（#DB741D）の8 px線 |
| 惰性区間 | 青（#1769B2）の8 px線 |

地図上の炎アイコンは`course_ignition_flame`を用い、コースコンテナ内（324, 423, 40, 40）に配置する。背面の円は（322, 421, 44, 44）とし、炎の中心に揃える。停止マークは（393, 310, 24, 24）。ON/OFF地点はアイコンだけで示し、文字ラベルは付けない。北向きの`N ^`は（407, 8, 60, 32）、32 px文字で表示する。地図下端にはGPSの状態文を重ねず、GPSの状態は別の表示領域で伝える。

これらを背景画像に焼き込まない。スタート・ゴールの点と周回更新線はすべてのダッシュボードで表示し、Settingsの保存値から配置する。周回更新線は実際の通過判定に使う基準経路上の距離`s_m`を中心とし、前後10 mの経路から接線を求め、その法線方向へ中心から各22 pxの線を引く。設定地点がコース回廊外、または画像範囲外なら線を表示しない。凡例は全コース共通でコースコンテナの最下端（x=10/120/230、y=454、幅100、高さ26）に`START`・`GOAL`・`LAP`の順で横並びに置く。画像範囲外に設定されたスタート・ゴールは端へ吸着させず、点と対応する凡例を非表示にする。現在位置の矢印は地点マーカーより前面に置く。プラン未設定の場合も3地点と現在位置を表示し、サンプルの火のマークを実際の指示として残さない。

初期実装の現在位置は生GPS座標を背景の変換行列で画素へ変換する。通過判定にだけ基準経路への投影と進行方向チェックを使い、画面上の位置をコースへ吸着させない。コース外/古い位置は別状態として表示する。

低速・停止時はGPS差分だけで矢印が回転しないよう、最後に信頼できた方向を保持するか方向なしの点に切り替える。GPSが古いときは最終位置を淡色・「位置更新なし」で示し、最新位置と誤認させない。

コース上の地点は原則として基準原点からの距離`s_m`で管理する。最終点と先頭点を結ぶ線分も補間対象に含める。同じ地点でも周回番号が違えば別の指示になり得るため、プランでは対象周回も保持する。

## 9. 走行プラン表示と将来更新

### 9.1 現行のmicroSDプラン

Tab5起動時に`/vega/strategy.json`を読み込む。フォーマット、7周の例、距離の原点と検証条件は[走行戦略データREADME](../assets/strategy/README.md)を参照する。対象コースと各周の経路・距離を検証し、不正なら案内を表示しない。Waitingでは1周目をプレビューし、Mainでは現在周回をモックと同じ橙色のエンジン使用区間、青色の惰性区間、点火炎とOFF四角で描く。GPS測位が有効なら次のON/OFF地点までの距離を下部中央に表示する。GPSが使えない場合も地図上の計画は表示し、距離案内の代わりにGPS欠損を示す。戦略は表示専用で、電装・点火GPIOを自動操作しない。

### 9.2 将来のAWS更新

AWSで基準プランと周回ごとの補正を作り、Tab5では採用済みプランを表示する。初期版は通信・解析なしでも、模擬データでUIを確認できるようにする。

UIが扱う情報の案:

- レースID、コースID・版、基準プランID、更新番号。
- 対象周回、適用可能な期限またはコース上の適用区間。
- 周回目標時間、エンジンON/OFFの予定地点、速度条件、加速・惰性区間。
- 変更理由の短い説明と、受信済み・採用済み・不採用の状態。

地図上の予定地点と、速度条件による実際の操作タイミングを区別する。速度しきい値が主条件の場合、マークは予定位置として扱い、条件を満たしていないのに「今すぐ始動」と表示しない。詳細な指示判定は解析実装時に定義する。

### 9.3 更新・通信断

- プラン見直しは原則1周ごととし、通常は周回途中で頻繁に表示を変えない。
- 受信しただけで地図を更新せず、対象レース・コース・周回・版・期限を検証してから採用する。
- 周回直後に届く更新の適用締切は別途定義する。締切後に届いた指示を遡って採用しない。
- 同じ更新の重複受信や古い更新で、表示を巻き戻さない。
- 通信断でも最後に採用した有効なプランまたは保存済み基準プランを表示する。利用できるプランがなければ「プラン未設定」とする。
- 有効な指示をキャッシュ表示している状態と、期限切れで使えない状態を区別する。
- 表示側で採用した版をシステム側へ通知できる設計とする。プランの確認操作を走行中のドライバーに毎回要求しない。

参考となる合意済み戦略は「最終盤の不要な再始動を避けて惰性でゴールを通過する」「ペースが速い場合は早めにOFF」「遅い場合はONの速度しきい値を上げて惰性を短縮する」。具体的なしきい値・補正量をUIにハードコードしない。

### 10.3 データと更新

表示モデルには値だけでなく、有効性、最終更新時刻、取得元を保持する。主な入力は速度、走行距離、位置、GPS状態、パルス到来、レース状態、プラン状態、現在時刻、NTP同期状態・最終同期時刻、電装指令と始動指令の状態とする。現行ハーネスには電装・エンジンの確認信号がないため、指令状態と実状態を区別し、実状態は不明として扱う。速度からエンジンON/OFFを確定的に推測しない。

**初期実装の更新周期:** 数値・地図は5〜10 Hz程度、経過時間と時計の秒表示の文字更新は1 Hz。受信・パルス計測・時間管理は描画とは独立させる。実際の入力レート以上に位置を新しく見せない。

LVGLオブジェクトへの変更はUI処理の実行文脈に集約する。通信処理や割り込みから直接UIを書き換えず、状態やイベントを受け渡す。EEZ再生成後もイベント登録・表示更新が保たれる構成にする。

## 11. 実装状況

承認済みのレイアウトに実データ処理を接続した。Waiting/Main/Finishedはレース状態から選び、現在の速度、停止時間を含む平均速度、周回、経過/TARGET、GPS位置と鮮度、電装指令、NTP状態を更新する。GPS位置は背景JSONの変換を用い、コース外の位置をコース上へ吸着させない。

SettingsのTARGETと3地点は変更・永続保存が可能。計測中の変更はUI/中核で拒否する。取消後は待機へ戻り、新規開始が可能。完走後は結果を保持する。電装と計測は独立し、ECU準備待ち・始動パルスの初期値は各1000 ms。

計測中のみSD記録と500 ms周期のテレメトリを生成する。SD障害時は警告して継続する。Wi-Fi/AWS未設定でも起動・計測・保存を行う。プラン未設定時は架空の指示を出さない。プラン解析・受信・復元・後送信は将来機能。

中核のホストテスト、実機書き込み、シリアル・SD記録の検証結果は[firmware-guide.md](firmware-guide.md)に記録する。画面目視、車両のGPIO波形、実GPS・リードスイッチ、AWS/NTP実接続は別途検証する。

## 12. 受け入れ条件

### 12.1 現行UIの表示・ナビゲーション

- 1280×720で文字・操作内容・地図が重ならず、速度・経過時間・目標時間と次の操作案内が車内から読み取れる。左右下隅の円形外枠だけは意図的にはみ出してよい。
- 速度の単位は`km/h`。見出しは`CURRENT SPEED (km/h)`・`AVERAGE SPEED (km/h)`とし、数値は両方とも独立した単位ラベルを省く。LAPの見出しはAVERAGE SPEED (km/h)と同じ32 px文字にする。全体・ラップとも目標の行は`TARGET`とし、`TOTAL TIME` / `LAP TIME`のグループで用途を区別する。
- 電源アイコンのみの電装トグルは左下、炎アイコンのみの点火ボタンは右下にある。青緑の電源アイコンと赤い炎アイコン付き円形操作で互いに区別でき、同じ主画面から大きなタッチ領域で操作できる。
- 円形外枠は画面外に少しはみ出してよいが、電源／炎アイコンは画面内に収まり、表示領域がスクロールしない。
- 手動補正は周回数の右側、計測開始／次の操作案内は左右の重要操作の中間に置かれ、相互に重ならない。次の操作案内は画面中央に揃った大きな文字で表示される。
- 電装トグルの選択状態は背景の塗り・枠の太さで分かり、点火操作だけで実測のエンジン運転状態を確定表示しない。
- 時計とNTP同期状態が24 px文字で小さく表示され、同期済み・未同期・最終同期後の継続表示の例を区別できる。
- `HEARTBEAT UI`、`PULSE INPUT`、`GPS FIX`等は小さなデバッグ表示になっている。
- 全体・ラップとも時間欄は現在の経過時間と`TARGET`のみ。残り時間・超過時間の数値や`LIMIT`表記はなく、目標未設定は`TARGET NOT SET`で分かる。
- Waitingには`START TIMING`があり、計測中の1〜6/7では`MANUAL` / `LAP +1`、7/7では赤い`GOAL` / `FINISH`を表示する。WaitingとFinishedでは操作を無効にする。ボタンの上下端はLAP見出し・周回数の表示範囲（y=444〜534）に揃う。手動ゴールは確認画面を経由する。
- 独立した速度の単位ラベル・コース注記・電装／点火ボタンの文字・電源アイコンのチェックマーク・プランの地図内説明や凡例を表示しない。
- メニューは開閉でき、表示中に背景の操作ボタンを押せない。設定画面へ移動し、現在のレース状態に対応するダッシュボードへ戻り、保持していた状態を確認できる。
- EEZで再生成してもアプリ側の操作・更新処理が失われない。

### 12.2 計測・機器制御・通信

以下は静的UIの表示確認だけでは充足しない。実データ・機器との接続後に検証する。

- 開始操作だけでラップ完了が加算されない。7周目開始と完走を区別する。
- 手動補正1操作で1回だけ反映され、同じ通過のGPS検出と二重加算しない。
- 全体時間はラップ更新・補正でリセットされない。目標超過時も経過時間を負数や折り返しにせず、そのまま表示する。
- 欠損・古い車速・GPS位置を正常な最新値として表示しない。
- 地図上の複数地点（両直線・両コーナー）でGPS位置と背景が一致する。画像の移動・拡縮後もずれない。
- 現在位置、ON/OFF地点、区間色を個別に更新できる。
- プラン未設定時に架空の操作指示を出さない。通信断でも時間・車速・GPS表示と手動操作が継続する。
- 古い・重複・期限切れのプランが表示を巻き戻さない。
- NTP補正・未同期はレース時間や開始操作に影響しない。
- 電装OFFでも計測・車速・GPS・表示は継続する。起動・再起動後に電装ON指令を復元しない。
- ECU準備待ち・パルス中にUI・計測を停止せず、電装ONごとに始動パルスを1回のみ送る。電装OFF時は待ち・パルスを解除する。
- 1/7で手動開始し、6回の有効な周回更新後に7/7となる。所定ゴールの通過まで完走しない。
- 計測取消で開始待ちへ戻り、手動開始でやり直せる。完走後の再計測操作は提供しない。
- Settingsで目標時間・3地点を編集でき、計測中の編集は画面とアプリケーションの双方で拒否する。
- 計測中のテレメトリをmicroSDへ保存する。SD障害を警告し、計測・表示・制御は継続する。
